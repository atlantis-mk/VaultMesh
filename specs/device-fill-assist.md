# 已配对设备填充协助

## ASSIST-001 授权与生命周期

执行 REQ-DEVICE-ASSIST-001、REQ-ANDROID-026 和 ADR-0047。仅同链路已配对设备通过独立版本化 mutual TLS 服务互通；mDNS 只包含版本及随机实例。授权逐设备区分号码和短信，默认关闭，须 Android Vault 解锁后设置。授权记录由平台凭据库保护并绑定当前 Vault 和设备证书。替换/恢复 Vault、证书改变及撤销配对必须失效。Android 系统锁屏与 Vault 锁定不终止已授权互通，但不得保留 Vault session。

“保持设备互通”开关默认关闭，用户在可见 Activity 首次开启后将布尔偏好保存在本机且不备份。服务使用 connectedDevice 前台通知；开关表示用户意愿，运行状态单独显示。打开应用、系统 sticky 服务恢复及 BOOT_COMPLETED/MY_PACKAGE_REPLACED 可以恢复已开启互通，不要求解锁 Vault；不处理 Direct Boot，必须等待系统用户解锁后的凭据存储。任务划除保留服务。关闭开关或通知停止必须先保存关闭，再清除连接、接收器和验证码；后续启动入口均先检查开关，停止同步不影响互通。v2 已交付到电脑的号码注册保留，验证码按电脑原始短时期限清除。系统强制停止不绕过；启动失败、缺通知权限或无网络显示等待/受限状态，不谎报运行，不承诺永久在线，不使用无障碍保活。

Rust 使用既有平台凭据存储封存版本化恢复记录，只含 Vault/副本绑定和当前密文 SHA-256 指纹，不含 Vault Key、解锁秘密、号码或代码。首次记录须在已解锁时建立；锁定恢复逐次核对当前文件指纹后仅恢复互通认证上下文，不建立 Vault session。Vault 原子写入成功后更新恢复指纹，失败不得发布新的恢复证明；副本变化、恢复/替换、损坏、未知版本、错误包装密钥或外部文件改变均封闭失败。新增记录不改变 Vault 格式，旧安装缺记录时提示解锁一次，后续恢复无需再解锁。逐设备授权仍须已解锁修改，开关和恢复记录不能代替号码/短信授权。

## ASSIST-002 来源与候选

每台手机提供默认 SIM 或现有加密备用号码，普通 DTO 仅含末四位。短信正文仅在接收时本地解析，明确验证码语义及唯一 4–10 位字母数字码才可产生候选。候选最多 20 个，内存保存两分钟；延迟到达的旧短信必须拒绝。普通候选只包含 opaque ID、来源、时间与设备，不含代码。来源和网站声明不得视作已认证匹配。无短信授权设备时清空缓存并停止接收。手动输入仅交付到当前电脑请求，不读剪贴板历史。

已授权号码必须通过 v2 订阅注册到电脑平台凭据库，绑定本机 Vault/副本、手机身份和证书；普通配对不能自动注册。注册记录不按时间过期，手机离线/停止服务仍可本地填入；手机号码/权限/授权变化在下一次认证连接更新或删除，本机撤销配对立即禁止使用并删除记录。手机完全撤销配对时，离线电脑可能无法再次认证收到撤销信息，必须在该电脑本地撤销配对清理注册号码；不承诺离线远程擦除。电脑切换或恢复 Vault 不得沿用其他绑定记录。号码不进入同步/备份/扩展存储。

电脑解锁 Browser 后必须预先建立认证订阅；手机主动推送注册变化与短时验证码，打开候选直接读取本地 Rust 状态。验证码只在内存保存，不超过手机原始期限；仅已消费 opaque ID 与原到期时间允许在平台凭据库短时封存，重启不得重放，过期清理，不含代码/正文/来源；重复快照和重连不得延长期限或恢复已消费代码。v2 按每台电脑本地一次消费，取消跨电脑唯一消费，点击无需手机在线，值从本机缓存生成 assignment；主动获取保留为旧手机和手动请求回退。

## ASSIST-003 请求与填充

Browser 必须独立解锁；电脑用户主动打开候选并逐次点选。目标网页允许普通 HTTP 和 HTTPS（包括 loopback、局域网及公网），不增加按协议的确认弹窗；拒绝 file/data/浏览器内部及其他非 HTTP(S) 页面。完整 origin 的协议和端口仍必须精确绑定，HTTP 与 HTTPS 不能互换。Android 到电脑的 transport 继续使用固定证书 mutual TLS。请求最长 120 秒，候选不得超过其原始有效期。绑定设备、Browser session、tab、document、frame、origin 和原始字段。取消、导航、隐藏、授权失效及重连不得复用结果。填充前验证原字段仍为空且可编辑，只生成一次性 assignment，不自动提交。号码只填明确电话/手机号账号字段；短信只填明确 OTP，排除密码、银行卡、明确 TOTP 与无语义数字框。v1 主动通道仍由手机全局一次消费；v2 推送按每台电脑本地一次消费，同机并发首次成功者取得结果，失败或未知交付不得自动重发秘密。

设备候选必须在对应已认证手机返回后立即呈现，不得等待其他设备或重复网络地址结束。单轮发现中同一服务实例成功响应后必须跳过其其他地址；失败地址仍允许回退。插件必须区分网页检查、空候选、连接失败与过期；每次桥接响应等待最多 10 秒，候选界面最长 60 秒后取消，不得永久显示连接中。无效响应必须明确失败，关闭或超时后的迟到请求须取消，迟到候选不得恢复界面或触发填充。手机号空候选提示必须指向号码授权、SIM/备用号码与服务状态，不得提示发送短信验证码。

明确手机号字段必须在注册、短信登录、密码登录、个人资料、收货、联系/预约和绑定手机号场景提供手机入口，不得依赖表单被识别为登录。页内入口、扩展目标筛选与桌面最终验证必须采用一致的字段语义：支持电话 autocomplete、中文“联系电话”等标签；明确短信/one-time-code 字段不得因 ID 含 phone 被当成手机号，手机号账号不得因相邻验证码或 OTP 表单上下文被当成验证码。密码流程名称出现在手机号字段 ID 中不等于密码字段；实际密码输入和明确密码标签仍必须排除。仅凭整个表单的 OTP 上下文不得向无语义数字框提供短信候选。

`autofill-test.html?suite=device-assist-tests`的专项验收必须包含上述场景、单框/六格短信及排除项；注册和登录原测试页也必须包含号码/短信字段。测试页必须明确 HTTP 与 HTTPS 均可进行显式互通填充，结果与日志不得显示完整号码/验证码。事件检查不能证明手机来源，专项通过必须由人工确认真实链路。

## ASSIST-004 兼容

不改变 Vault format 4 或 Browser RPC v2。新操作经能力探测启用；旧端不支持时隐藏入口并提示升级。Google SMS Autofill 保持仅供手机本地当前字段使用。新 RECEIVE_SMS 接收路径受系统与安装器控制；Android 17 可能延迟验证码，不可用时允许手机显式手动交付。不得把编译或模拟测试当作真实短信与跨平台安装验收。
