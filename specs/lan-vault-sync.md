# 局域网 Vault 自动同步

## LAN-SYNC-001 数据与合并

仅已授权的同链路 macOS/Windows 客户端可以同步；锁定仅收发密文，解锁才验证合并。Login/TOTP/恢复码、card、SSH、identity、Secret、Service、API environment 及其 trash/history 必须按 kind + UUID 同步。旧 BE=0 Passkey、邮件连接凭据、审计、设备设置、Agent/Browser 权限、内部 connector、SSH 本机部署绑定不得同步。不同 UUID 保留独立条目。

Core 必须为每个同步记录持久化 HLC 和副本 ID，整记录采用确定性 LWW，败者保留在加密冲突历史。同版本重复收取必须幂等；编辑、永久删除、历史清理必须同事务记录版本和不含秘密的 tombstone，首版不得自动回收墓碑。历史清理还必须持久化按条目的 HLC 清理版本，丢弃版本不高于它的历史，覆盖清理时尚未见过的离线历史；冲突历史使用全局清理版本。回收站与活动记录必须共享同一逻辑条目键，避免复活。引用失效时必须 fail closed，不能继续沿用旧 target 或已批准计划。

## LAN-SYNC-002 授权与网络

新配对界面必须说明配对即授权当前 Vault 的双向同步；旧配对双方必须各确认一次。授权必须绑定双方 Vault 和已固定证书的设备身份。首次绑定以已授权的认证连接交换 Vault 身份。切换或恢复 Vault 后不得沿用旧绑定。同步协议独立版本化，使用 mutual TLS、大小/数量/超时限制，版本清单和变化记录仅存在 Rust 敏感内存。协议 v2 分块搬运加密批次，单帧上限 128 KiB、完整明文批次上限 64 MiB、同步记录上限 100,000、设备/发现表上限 32、每 Vault 持续连接上限 32、并发握手上限 8；网络写入超时 10 秒、含密钥落盘的握手整体时限及未完成帧时限 30 秒；持续会话空闲 15 秒心跳、30 秒无响应断开，单批次传输时限 120 秒；失败以 1–60 秒指数退避并附加不超过 1 秒随机错峰。超限必须失败且不部分落盘。

服务必须独立于页面维持已授权连接，数据落盘后主动推送；重连交换版本并主动补齐。配对发现仍保持显式十分钟窗口；同步发现不得公开持久设备/Vault 标识。桌面/系统锁定必须清除对应解密会话与明文缓冲区，但可以继续搬运密文；睡眠、退出、切换或撤销必须立即关闭对应连接。Browser/Agent 独立解锁可以合并本机收件箱，但不能自动获得同步配对授权。接收记录必须与当前本地修改重合并，原子提交成功后才能确认；重复或确认丢失必须可重试。关闭同步不删除副本。

## LAN-SYNC-004 锁定收发与多副本

方向通道必须按 peer、固定证书、双方 Vault 和随机 epoch 绑定，首次建立须双方解锁交换方向密钥。密钥仅存在 core 加密状态与有界 TLS 握手缓冲区；完全锁定后不能解密或给其他设备重新封装。已有旧同步授权须明确升级后才允许锁定传输。

Vault mutation 成功后必须生成可恢复的加密发件缓存；缓存失败保留已提交数据，状态显示失败并在可用解锁会话重试。冷启动使用缓存前必须验证 OS-protected 路由证明及当前 Vault 指纹，缓存不匹配时等待解锁重建，不继承旧授权。收件缓存不得包含标题、条目 ID、凭据值、明文清单或通道密钥。

每 Vault 密文缓存上限 256 MiB，全进程未完成接收上限 256 MiB；每 peer 只保留有界累计差异及最新收据，发送基线只能由认证合并收据推进；接收存储确认不得推进基线。分块全部保存后才报告已送达；解密、引用验证和原子提交成功后才生成已合并收据。队列满、帧损坏和断线均不得部分合并；对端保留未确认变化以便重试。

三台以上设备必须保留原始 HLC/副本版本，重复转发不生成新修改。连接、队列和重试记录必须有界并随发现过期清理；失败采用指数退避与随机错峰。每个接收者分别去重、确认和撤销；单边撤销不能隔离仍通过其他已授权路径可达的设备。数据解锁合并后可以通过各自授权边转发，锁定设备只收发属于该连接的密文。
