# ADR-0020：锁定密文收发与多设备事件同步

## 状态

Accepted。用户明确授权按推荐方案实施锁定密文暂存、解锁合并与三个及以上设备同步。

## 决策

替代 ADR-0019 的仅 desktop 解锁期间联网限制；其 Vault 加密、版本合并及 Passkey 决策继续适用。完整当前网络与队列行为由 `specs/lan-vault-sync.md` 所有。

每条已授权连接使用独立的双向密文通道。方向密钥由 core 随机生成，只在初次双方解锁的固定证书 mutual TLS 连接内交换，并与双方 Vault、设备证书和通道 epoch 绑定。重新启用允许在双方解锁的固定证书连接内为同一 Vault 轮换方向 epoch，并拒绝旧通道包。方向密钥加密保存在本机 Vault；不得使用或传输主密码、Vault Key，也不得由 OS key store 提供凭据解密能力。由随机方向密钥经域隔离 HMAC-SHA256 分别派生 AEAD 与内容身份子密钥；使用已有 XChaCha20-Poly1305、随机 192-bit nonce 和域隔离 AAD；队列仅持久化密文及有界路由元数据。完全锁定后不保留方向密钥。

解锁的 runtime 负责生成发件密文和验证合并收件密文，Browser/Agent 的独立授权也可以驱动本机 core 更新。锁定服务只搬运已经生成的密文。可恢复密文缓存与 Vault 的事务分开：Vault 是事实所有者；先成功提交 Vault，再发布密文缓存。缓存失败不得撤回已保存用户数据、不得报告送达；下一次解锁/操作重建并重试。冷启动必须验证 OS-protected 路由证明与 Vault 文件指纹，不能从可修改 sidecar 恢复授权。首次通道建立及缓存过期需要一次解锁。

每个接收设备独立保存已接收与已合并确认。只有通过认证的合并确认才能更新 Passkey 备份状态。重连主动比较密文版本；分块完整接收后才报告已接收，全部解密记录验证并原子落盘后才报告已合并。失败/确认丢失由幂等重试恢复。

多设备按原始记录版本转发；不得把收到数据记为新编辑。锁定设备不得重加密给其他接收者，也不得自动获得第三方信任。撤销一条边不能撤回已复制数据或阻止其他授权边传播。

## 兼容与后果

同步协议升级并隔离旧协议。format 4 的同步授权增加带默认值的私有通道状态；旧 format-4 reader 的 deny-unknown-fields 必须拒绝新 payload，禁止旧 writer 丢字段。首次建立通道必须经明确同步授权；已有同步授权不会自动升级为锁定期网络权限。Vault Key/KDF 与 format-3 升级备份保持不变。恢复轮换 Vault/副本/通道身份并清除队列授权。

拒绝完全锁定仍保留解密能力、使用一个群组密钥自动信任所有设备、仅 TLS 加密但在锁定磁盘保存明文、无上限离线队列、把密文送达当作凭据可用，以及无限频率重建 TLS。
