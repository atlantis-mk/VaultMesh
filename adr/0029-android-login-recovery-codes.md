# ADR-0029：Android Login 恢复码与文档边界

- 状态：Accepted
- 日期：2026-09-18
- 关联 Work：`CHG-2026-054-android-recovery-codes`
- 关闭 OPEN：无

## 背景

桌面端已把恢复码作为 Login 受保护字段，并要求每次查看和复制都验证主密码。Android 文档选择器会触发 Activity 后台锁定，不能在文件框期间保留解锁会话或明文编辑草稿。

## 决策

- Android Login 安全摘要只增加恢复码存在性。固定 JNI 接收有界替换文本或明确清除，Rust 按换行和完整编号双栏规则解析，由 core 验证并原子提交；普通编辑不读取或改写已有恢复码。
- 用户每次查看须重新输入主密码；固定 JNI 返回有界恢复码列表，只留在当前前台 Compose 弹窗。逐码复制再次验证主密码，单个值只进入 Kotlin 特权剪贴板服务，并沿用 sensitive 标记和所有权清理。
- Kotlin 用一次性 `content:` 文档 URI 有界读取 UTF-8 到内存，不创建明文 staging 文件。选择器使应用锁定；重新解锁后才读取并打开待确认草稿。取消、后台化或锁定清除草稿和查看值。
- 仅在导入内容原样保存成功后，才提供单独源文档删除确认。用户确认后复读比对内容摘要，并检查文档支持删除；改变、无权限或失败时保留文件。URI 与摘要仅在当前 Activity 内存中存在。

## 原因

core 保持恢复码所有权和密码验证。文件选择跨越锁定边界，只保存不含秘密的一次性 URI，避免明文落盘或延长授权。

## 后果

文件选择返回后用户须重新解锁；提供者可能不支持删除，应用只能报告源文件仍保留。JVM 字符串无法可靠原位擦除，必须在取消、提交与锁定时立即解除引用。

## 被拒方案

- 将恢复码加入普通 Login 详情：列表/编辑会无条件暴露受保护值。
- 文件框期间保持解锁或把导入内容暂存私有明文文件：扩大后台与崩溃残留风险。
- 在保存前删除源文件：保存失败会造成不可恢复的数据丢失。

## 验证

`CT-ANDROID-JNI-011`、`AT-ANDROID-012` 与 `GATE-3A`。
