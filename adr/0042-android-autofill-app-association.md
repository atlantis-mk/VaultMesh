# ADR-0042：Android 自动填充的网站候选与应用关联

## 状态

Accepted。补充 `ADR-0040` 的未关联候选选择与包签名绑定策略。

## 决策

原生应用的包名和显示名称不构成网站所有权证明。Autofill 授权后可以把包名拆成有效片段，去除通用前缀，与 Login 标题或 HTTPS 主机标签比较；也可以比较应用显示名称。相似结果仅显示为“可能相关”，不得视为已关联或跳过目标确认；候选只在 VaultMesh 认证页显示，不向目标应用披露。

成功填充后的当前目标与条目 ID 选择顺序以 Android Keystore AES-GCM 加密，写入应用私有且不备份的有界记录。最近一次选择在下一次候选列表排第一，其他已选候选随后排列，再按精确绑定、HTTPS origin 和相似性排序。该记录不含用户名、密码或解锁状态，不是授权依据；解密失败或记录丢失仅退回默认排序。

用户首次选择未关联条目时，可以选择“仅本次填充”或“确认并记住关联”。两者都必须先确认包名和可选 origin。记住关联时，Rust 在交付 Dataset 前将当前包名、完整签名集合摘要及可选 origin 写入该 Login 的加密 `additional_urls`，复用现有原子提交与回滚。写入失败时不得交付凭据；单次授权照常消费。后续只有精确签名与 origin 绑定匹配才列为“已关联此目标”。用户可在 Login 编辑页移除关联 URL。

Android Verified App Links 与网站的 Digital Asset Links 可提供更强的应用网站证明，但不能由包名、显示名称或未验证的链接处理声明推导。此切片不增加在线域名查询，也不把推测结果写成可信关联。用户选择后的显式绑定是当前可离线工作的路径。

## 原因与替代方案

QQ 等原生登录页可能没有 web origin，已有网站 Login 因此没有可用于精确推荐的来源。名称与主机标签能改善首次检索，但应用名称可由应用控制，所以仅影响排序并保留首次交付确认。直接按应用包名猜网站或无确认自动绑定会扩大钓鱼风险。

## 验证

`CT-ANDROID-AUTOFILL-001/002` 覆盖包名片段提示、选择顺序、签名和 origin 精确匹配、确认与记住的单次消费、原子回滚及 JNI/UI 契约；`AT-ANDROID-023` 在真机验证 QQ 网站账号进入“可能相关”，选择后在下一次排第一。
