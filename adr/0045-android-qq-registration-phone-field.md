# ADR-0045：QQ 注册手机号字段的窄范围识别

## 状态

Accepted。QQ 注册页的系统 Autofill 请求只有一个无提示的纯数字 `EditText`；当前通用识别规则无法安全区分它与验证码或 PIN。

## 决策

仅当系统请求的目标包和 Activity 分别精确为 `com.tencent.mobileqq` 与 `com.tencent.mobileqq.activity.RegisterPhoneNumActivity`，且表单仅有一个可编辑字段、该字段聚焦、可见、启用、原生 `EditText`、无 Autofill hint、无文本 hint、无 HTML 信息、无 web origin、输入类型恰为数字并且最大长度为 15 时，将该字段视为手机号形式的用户名字段。任一条件不符即按现有规则拒绝。仍以请求时的实际包签名绑定 Autofill 目标，不把 Activity 名称或应用显示名称当作凭据关联依据。

这个字段只允许用户点选本机号码候选，或通过 VaultMesh 通用入口选择适用的已有账号；不提供字母随机用户名，不自动填入或提交。纯数字账号字段不单独触发保存提示。随机用户名继续只对可识别的文本注册账号字段提供。

## 原因与替代方案

把所有无标签数字框推断为手机号会把候选显示在验证码、支付金额和 PIN 字段，扩大个人号码暴露面。QQ 的精确 Activity 与结构守卫将例外限定在已观察到的注册表单；应用更新导致结构变化时安全退回无候选。系统不提供注册语义的通用保证，故不宣称覆盖所有第三方注册页。

## 验证

`CT-ANDROID-AUTOFILL-002/003` 覆盖 QQ 精确目标与字段结构的正反例、手机号独立 Dataset、随机用户名不进入数字字段；`AT-ANDROID-024` 在 QQ 真机注册页验证候选与点选行为，不读取或记录输入值。
