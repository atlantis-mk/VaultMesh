# ADR-0031：Android 卡片编辑详情与完整字段提交

- 状态：Accepted
- 日期：2026-09-18
- 关联 Work：`CHG-2026-056-android-card-fields`
- 关闭 OPEN：无

## 背景

Android 基础卡片编辑只覆盖标题、持卡人、卡号与到期及安全码/PIN。core 还保存发卡机构、卡组织、账单地址、备注、文件夹、收藏和主密码复验设置。移动端若分步修改，可能产生部分提交；若只按基础字段重建，又会丢失桌面字段。

## 决策

- 卡片列表仍只返回安全摘要；用户明确打开编辑器后，固定 `cardEditorDetail` 仅返回补充字段，不含完整卡号、安全码或 PIN。取消、切换、锁定、后台或迟到详情清除草稿。
- 新的固定 `addCardComplete` 与 `updateCardComplete` 接收基础字段和严格类型化、有界 JSON 补充字段。Rust 拒绝未知键与超限输入，core 在一次候选 mutation 中验证全部字段并原子提交；空卡号继续保留旧值，安全码/PIN 的明确清除与替换互斥。
- 旧基础操作暂保留供现有兼容路径；Compose 新建和编辑使用完整操作。补充字段在编辑草稿与 JNI 输入之外不得进入日志或持久 UI 状态。

## 原因

按用户编辑动作读取并整体提交可同时保护卡片数字秘密、保留桌面元数据和避免跨两次写盘的半完成状态。固定 DTO 不引入通用方法路由。

## 后果

账单地址与备注短时进入 JVM/Compose 内存，取消和锁定必须解除引用；文件夹与复验设置会影响其他平台的展示和访问策略，须用跨端 Vault 回归及真机验证。

## 被拒方案

- 将补充字段全部加入列表：无请求时暴露账单地址与备注。
- 先保存基础字段再单独保存补充字段：第二次失败会留下部分更新。
- 把完整卡号、CVV 和 PIN 回填编辑器：扩大秘密暴露面。

## 验证

`CT-ANDROID-JNI-012`、`AT-ANDROID-014` 与 `GATE-3A`。
