# ADR-0044：Android 锁定态自动填充候选预览

## 状态

Accepted。用户要求系统候选先显示多个相关账号，点选后再验证；已有当次有效授权时直接填充。

## 决策

Android 可以在锁定态向系统 Autofill 下拉框提供有界的 Login 安全摘要预览。预览只含条目 ID、用户名、标题和 HTTPS 主机，不含密码、完整 URL、关联签名、主密码或授权。摘要由已解锁的前台列表或当次 Autofill 授权后的候选生成，使用无用户认证要求的 Android Keystore AES-GCM 密钥加密，原子写入应用私有且不备份的文件。此决定允许设备解锁后、Vault 仍锁定时在目标应用的系统候选中显示相关用户名；设备屏幕观察者可能看到这些名称。文件绑定当前加密 Vault 字节的 SHA-256；文件改变、解密失败、无 Vault 或数据过限时预览失效。该文件不授予填充权限。

服务仅对当前包签名、可选 HTTPS origin 和既有私有加密选择历史筛出少量相关账号；显示名称和 URL 主机的相似性只影响排序，不构成应用归属证明。每个可见候选绑定独立的一次性系统请求及条目 ID。点选后仍由 Rust 独立授权重新读取当前 Vault、验证目标签名/origin 和条目归属；未关联目标须明确确认；要求主密码复验的条目须使用主密码。有效的当前请求授权可直接消费，锁定态或跨请求不得因为预览缓存而免验证。无可用预览时继续提供通用 VaultMesh 入口。

## 原因与替代方案

现有候选仅能在认证后从解密 Vault 返回，因此系统下拉框无法先显示账号。把密码或可复用解锁 grant 缓存在 Kotlin 会扩大秘密与权限边界；只缓存加密安全摘要，并在最终填充前用 Rust 重新验证，保留单次授权和显式关联确认。

## 验证

`CT-ANDROID-AUTOFILL-001/002` 验证缓存加密、Vault 变化失效、候选排序/上限、点选条目与授权绑定、取消/过期/签名变化拒绝和主密码复验；`AT-ANDROID-023` 真机验证先显示多个相关账号、点选后生物识别/PIN/主密码、已授权直接填充及未匹配确认。
