# ADR-0047：已配对设备号码与短信填充协助

## 状态

Accepted。用户于 2026-09-27 批准完整方案并要求实施；号码和短信均按设备一次授权，手机锁屏仍可提供，电脑逐次点选。

## 决策

共享 Rust LAN crate 拥有独立版本化的互通 transport，复用已有设备身份、证书固定、mutual TLS 与同链路验证。配对和 Vault 同步不隐式授权互通。Android Kotlin 拥有号码来源、系统短信接收、权限、前台服务和手动输入；固定 JNI 将有界结果交给 Rust 请求状态机。桌面 Rust broker 持有短时请求，Browser 仍须独立解锁并由用户手势生成绑定原始文档/字段的一次性 assignment。

互通授权以平台凭据库保护，绑定当前 Vault、本机与对端设备证书；恢复、替换和撤销失效。即时值不进入 Vault、同步、备份、日志或普通 UI DTO。独立互通权限允许后台/锁屏处理号码与两分钟短信缓存，但不保留或获得 Vault 解密会话。原 Android 本地 SMS Autofill 的字段授权不复用。

新增 RECEIVE_SMS 仅用于用户主动启用的互通服务；不读取历史收件箱、不发送短信、不请求默认短信或系统伴侣角色。Android/安装器拒绝或延迟验证码时提供显式手动输入回退，不降低 targetSdk。不保证所有短信自动获取。用户追加要求保存互通开关且无需解锁 Vault 恢复：首次从可见 Activity 开启，之后允许系统 sticky 恢复和系统用户解锁后的开机/更新恢复，划除任务保持运行；显式关闭保存偏好，强制停止不绕过。独立的加密恢复记录绑定当前 Vault 密文指纹和副本，不包含解锁能力。此追加决定替代原先服务每次手动启动、划除任务即停止的限制。不得使用无障碍服务充当保活工具。

## HTTP 页面支持的追加决定

用户于 2026-09-27 明确要求 HTTP 页面也允许电脑逐次点选的跨设备填充。本次修订接受这一浏览器信任边界：普通 HTTP 与 HTTPS 页面均可使用，包含 loopback、局域网及公网 HTTP；不增加逐站授权或额外确认弹窗。用户手势仍不等于 HTTP 页面可信，HTTP 内容可被网络攻击者改写，目标页面及其脚本在填入后可读取值；产品不承诺用户手势消除该风险。

这只改变目标网页允许的协议。Android 到电脑的独立 LAN 通道继续使用固定证书 mutual TLS，不能降级成明文。Browser 独立解锁、逐次电脑点选、逐设备手机授权、原 tab/document/frame/完整 origin（含协议和端口）绑定、空字段重验、消费次数按后续推送决定执行，不自动提交仍然必须保留。其他浏览器能力原有的 HTTPS 要求不随此决定改变。

## 注册号码与被动推送的追加决定

用户明确要求授权后注册号码、电脑本地读取，并以被动推送为主、主动获取为补充。接受号码从瞬时值改为桌面平台凭据库中的持久注册记录；记录绑定本机 Vault/副本、手机身份及固定证书，不进入 Vault 同步、备份、renderer 或扩展 storage。已有逐设备号码授权允许建立注册，单纯配对不授权。手机离线或停止服务仍可使用已注册号码；本机撤销立即删除，手机端撤销/换号/恢复必须在下一次认证连接通知电脑更新或删除，离线电脑不承诺即时远程擦除。

增加独立 v2 认证订阅，手机在连接内主动推送号码注册变化及短时验证码，不进行局域网明文广播。验证码仅在 Rust 内存保存原始两分钟期限，普通 DTO 仍仅返回脱敏候选。用户追加选择各授权电脑直接使用已推送验证码，因此 v2 改为每台电脑本地一次消费，取消跨电脑全局唯一消费；点击无需联系手机，值从本机短时缓存生成 assignment。被动推送不绑定页面，最后一次本地消费和填充必须绑定当次 Browser 请求。已消费 opaque ID 与原到期时间允许在平台凭据库短时封存以阻止同机重启重放，不含代码/正文/来源且仅保留到原始两分钟期限。旧 v1 主动通道继续作为兼容与手动请求回退。

## 替代方案

拒绝借用 Vault 同步缓存保存验证码、配对即开放远程读取、让 Google 本地 Autofill 授权跨目标使用、用通知监听替代受限短信接收，以及未经用户选择直接填入验证码。

## 验证

CT-DEVICE-ASSIST-001/002 与 AT-DEVICE-ASSIST-001；平台状态以真实验收结果为准。
