## 兼容与迁移

- 操作员说明当前源码和 R2 desktop/Android Review channel 已是 `0.1.7-review`，因此本准备按既有 patch+1 模式前进到 `0.1.8-review`。本任务没有读取或写入 R2。Test channel 保持独立。
- 已发布的不可变资产不得覆盖。Review updater 不支持降级。本记录不创建 Git Tag，也不复用或改写历史 Release 记录。
- Vault format、Browser RPC 与 Native ABI 不变。
- Chrome 固定 ID `bdneegbnjbheblmamalplnddbodcghbg` 与 Firefox Gecko ID `vaultmesh@atlantis-mk.github.io` 保持不变。
- 直接从 v0.1.1–v0.1.3 升级的安装必须重新设置 PIN/生物识别并重新配对。那些旧钥匙串条目不再被读取或自动删除，会留在系统钥匙串中。v0.1.4 及之后已经迁入 `device-credentials.enc` 的安装继续使用该文件。空 AAD 的旧文件在解密成功后仍必须重封。回退旧桌面版本不能假定仍能读取已迁移的根钥匙串条目；出现问题使用更高版本补偿。
- Android 继续使用既有 Review release keystore。签名策略未改。CI 仍须核验固定签名指纹和各 ABI 的派生 versionCode（108000–108003）。
- WiX 占位版本保持 `0.0.9`。签名、notarization 与 Authenticode 策略未改。

## 已知问题与补偿限制

- 本版本不是 Stable。平台 AT、Apple notarization、Windows Authenticode 与安全发布检查都未完成。文档和本机脚本通过不授权公开。
- 协调者正在确认将来公开 Review 是否有明确的用户例外。本准备不假定该例外已经成立，也不修改 GATE-6。
- `AT-SEC-002`、`AT-UPDATE-REVIEW-MACOS-001`、`AT-UPDATE-REVIEW-WINDOWS-001`、`AT-ANDROID-RELEASE-001` 以及上表所列平台 AT 都还未执行。Review 构建不计为这些 AT。
- Doctor 给非 Chrome 浏览器的链接跟随包版本。`v0.1.8-review` tag 不在本变更中创建，链接在该 tag 存在前不可用。
- 直接从 v0.1.1–v0.1.3 升级会失去尚未迁入统一凭据文件的 PIN、生物识别和配对，需要重新设置。这不是静默恢复。
- macOS 根钥匙串失败或取消时，桌面仍按既有规则降级启动：主密码解锁可用，PIN、生物识别和配对停用。
- Linux 上的文档和脚本验证不能代替 macOS、Windows 或 Android 的安装态验收。
