`0.1.6-review` 已包含 `e529e38cd8f756b93838f85861e5868514e31081` 的 ACL 修复：ad-hoc 文件钥匙串按 `SecTrustedApplicationCopyData` 的不透明身份比较信任应用，并试图在根条目内部把污染或旧 ACL 规范化一次。其后的 #15 说明，系统总会补上一条默认 PartitionID ACL，使“全部 PartitionID ACL 都精确匹配”的判断到不了，于是每次启动都再次调用 `SecKeychainItemSetAccess` 并追加 ACL。`a414d772a199a53c5bf28763de7dd02ab262b497` 改为只由用户主动启动的桌面主程序、在每个 main/Host cdhash 组合下迁移一次：读取秘密、删除根条目，再以仅信任包内主程序与 `vaultmesh-native-host` 及当前分区列表的 Access 重建；成功后写入非秘密迁移标记。标记匹配时不再检查或修改 ACL，也不再使用 `SecKeychainItemSetAccess`。重建失败必须恢复原秘密。Native Host 遇到未迁移或缺失条目时 fail closed，不得请求系统修改或创建授权。用户取消或迁移失败必须 fail closed。根钥匙串不可用或用户取消修复时，桌面主程序降级启动：凭据存储拒绝一切读写，主密码解锁仍可用，PIN、生物识别和配对停用，并显示不含秘密的原因；不得因此崩溃。未签名或签名不一致、无法在 `.app` 内形成完整共享计划的发布构建，必须在访问钥匙串前失败，不得退回普通 keyring。`AT-SEC-002` 仍未执行。

`cb4a6ab1dfa2b37b7c7954a8209e323d26e82413`（#13）只在 `AGENTS.md` 记录 Linux Cloud Agent 的验证边界：可以验证 core、脚本、桌面 renderer 契约和浏览器扩展；Tauri 2 产品 shell 仍只在 macOS / Windows 上编译和运行。没有用户可观察的产品行为变化。
